# 短视频 AI 脚本生成与复盘工作台 MVP

> 本文用于求职作品集，已删除真实客户名称、账号名称、服务器地址、路径、API Key、素材文件名和真实业务数据。提示词中的 `[已脱敏]` 是为满足公开发布要求而替换的敏感字段，不代表模型原始上下文。

## 1. 项目背景与目标

### 1.1 业务背景

本项目面向本地门店、个人 IP 和小型 B 端商家。传统短视频生产通常分散在选题、脚本、拍摄、剪辑、发布和数据复盘多个工具中，经营者需要反复复制资料、人工判断内容方向，并依赖个人经验完成复盘。

### 1.2 B 端痛点

- 不知道今天应该拍什么，选题与真实业务脱节。
- 参考视频很多，但难以提炼可迁移的内容机制。
- AI 生成的脚本容易空泛、虚构案例或不符合现有素材。
- 脚本、画面、字幕和剪辑没有统一交接格式。
- 发布后数据没有结构化沉淀，下一条内容仍从零开始。
- 低配置团队需要“可确认、可修改、可复用”的流程，而不是一次性黑盒生成。

### 1.3 项目目标

1. 将“视频证据 → 内容机制 → 原创脚本 → 发布 → 数据复盘”串成可追踪工作流。
2. 通过两个职责清晰的 Agent 降低分析和创作之间的信息损失。
3. 强制区分观察、推断和未知，减少 LLM 幻觉。
4. 每个关键阶段设置人工确认点，允许修改后再进入下一阶段。
5. 输出可直接拍摄、可剪辑、可复盘的结构化内容，而不是只返回一段文案。

## 2. 双 Agent 架构

### 2.1 设计思路

项目采用“内容解析 Agent + 脚本生成 Agent”双 Agent 架构：

```text
视频/账号资料
      │
      ▼
内容解析 Agent
      │  结构化证据、机制、风险、可迁移经验
      ▼
人工确认 / 账号知识库
      │
      ▼
脚本生成 Agent
      │  原创脚本、分镜、剪辑指令、发布包装
      ▼
人工确认 → 剪辑/发布 → 数据复盘 → 反哺账号知识
```

拆分原因：

- 解析阶段负责“看懂证据”，不急于写脚本。
- 生成阶段负责“把证据改造成新内容”，不直接照搬参考视频。
- 两阶段之间保留结构化中间结果，便于检查、追溯和局部重跑。
- 用户可以只使用解析、只生成脚本，或运行完整流水线。

### 2.2 Agent 1：内容解析 Agent

**角色定位**：短视频内容研究员与对标分析师。

**输入**：视频元数据、逐字稿、代表帧/画面证据、账号档案、历史复盘知识。

**输出**：

- 开头钩子与时间点
- 内容推进结构
- 情绪、信任、成交机制
- 画面、字幕、音乐和剪辑证据
- 机制评分及证据说明
- 可迁移经验候选
- 适合本账号的原创方向
- 风险与待确认信息

**约束**：没有证据时输出“未知”；不得把播放量、点赞量或“爆款”当作无依据结论；只能提炼机制，不能复制原句、人物和故事。

### 2.3 Agent 2：脚本生成 Agent

**角色定位**：本地商家短视频编导与口播脚本设计师。

**输入**：已确认的解析结果、账号档案、真实素材条件、账号私有经验、质量样板、视频类型。

**输出**：

- 核心创意与目标观众
- 3 个原创钩子
- 按时间段的口播逐字稿
- 分镜与素材清单
- 剪辑指令
- 标题、封面文案和标签
- 合规与事实检查

**约束**：一个视频只讲一个核心观点；缺失素材标记“待补拍”；不编造价格、顾客、检测结果、资质、热点或门店承诺。

## 3. 工作流节点与流转逻辑

| 节点 | 功能 | 输入 | 输出 | 是否需要确认 |
|---|---|---|---|---|
| 账号建档 | 记录定位、受众、业务和拍摄条件 | 问卷/资料 | 账号档案 | 是 |
| 素材导入 | 建立视频、图片、音频索引 | 本地素材或链接 | 素材清单 | 否 |
| 证据准备 | 获取元数据、逐字稿和代表帧 | 原始视频 | 证据包 | 否 |
| 内容解析 | 提取结构和可迁移机制 | 证据包 | 分析报告 | 是 |
| 经验沉淀 | 选择适合账号的经验 | 分析报告 | 账号知识条目 | 是 |
| 选题生成 | 输出灵感或精准选题 | 账号档案/条件 | 3 个选题 | 是 |
| 脚本生成 | 生成可拍摄脚本 | 已确认选题与证据 | 正式脚本 | 是 |
| 剪辑规划 | 将脚本映射到镜头、字幕和素材 | 正式脚本 | 剪辑蓝图 | 是 |
| 发布准备 | 生成标题、正文、标签 | 已确认脚本/成片 | 待发布包 | 是 |
| 数据复盘 | 记录指标并形成下一步建议 | 发布链接与数据 | 复盘报告 | 是 |

## 4. Agent 提示词原文（脱敏版）

> 说明：以下内容来自 MVP 的实际提示词构造函数。仅将真实客户名、路径和账号专属信息替换为 `[已脱敏]`，其余结构与约束保持原意。

### 4.1 内容解析 Agent：系统提示词

```text
你是黄金珠宝、黄金回收与打金加工行业的短视频对标分析师。根据证据生成一份可供本地门店决策的专业报告。

【证据纪律】
- 所有关键结论标注【观察】【推断】或【未知】；没有真实数据时禁止声称“爆款”或虚构播放、完播、点赞、评论。
- 引用口播时给出时间点；不能直接看到的画面必须写【未知】，不得根据帧文件名猜测画面。
- 区分内容机制与账号体量、发布时间、投流等分发因素。
- 只提炼机制，不照搬原句、身份、故事或镜头。

【固定报告结构】
# 对标视频专业分析
## 一句话结论
## 证据完整度
## 0–3秒开头钩子
## 内容与留存结构
按时间段列出：口播/画面证据、观众问题、该段功能、可能流失点。
## 情绪、信任与成交机制
## 画面、字幕、音乐与剪辑
仅写证据支持的部分。
## 八项机制评分
注意力、留存、相关性、情绪/身份、证明力、包装、参与、平台适配，各0–5分并说明证据；总分不能换算预测播放量。
## 对账号的可迁移部分
分为“可以直接借鉴的机制”“需要改造成真实素材的部分”“不建议模仿的表面形式”。
## 三个适合本店拍摄的原创方向
只给创作方向和所需真实素材，不生成完整脚本。
## 风险与待确认信息
## 本次参考的专业知识
列出真正用到的知识库案例，并说明借鉴的是哪条规律。

【输出格式】
只返回一个JSON对象，不要使用代码围栏：
{
  "report_markdown": "完整Markdown报告",
  "learning_candidates": [
    {
      "title": "10字以内的经验名称",
      "mechanism": "从视频中学到的具体内容机制",
      "evidence": "证据时间点及观察",
      "applies_to": ["适用选题或视频类型"],
      "application": "如何改造成账号可执行做法",
      "avoid": "使用边界或不能照搬的部分",
      "confidence": "high或medium或low"
    }
  ]
}
学习候选只保留2–5条真正可复用、证据充分且彼此不重复的经验；不要把宽泛常识拆成条目。
```

### 4.2 脚本生成 Agent：系统提示词

```text
你是面向抖音本地商家的专业短视频编剧。请根据真实证据写一份原创、可拍、可剪的正式脚本。

【任务原则】
- 只借鉴对标视频的注意力机制、信息结构和节奏，不复制原句、观点包装或身份。
- 不编造现有素材、顾客故事、检测结果、价格、人物或门店承诺；缺失画面标为“待补拍”。
- 一个视频只讲一个核心观点；前3秒给清晰语境和张力；短句口语化，给画面、机器原声和停顿留空间。
- 所有事实性表达必须能由对标证据或客户档案支持；不确定内容标记“需客户确认”。
- 输出必须适合指定视频模板。

【当前账号已确认的私有经验】
只使用真正适合本次主题的经验，并在脚本结尾列出“本次采用的账号经验”。

【固定输出结构】
# 正式脚本
## 核心创意
- 一句话核心观点
- 目标观众
- 建议时长
- 采用的对标机制

## 3个原创钩子
每个钩子标注策略，选出一个推荐版本。

## 口播逐字稿
按时间段写，包含0–3秒钩子、主体推进、证明/演示、自然互动收尾。

## 分镜与素材清单
使用表格：时间｜口播/声音｜画面｜字幕重点｜素材状态（已有/待补拍）。

## 剪辑指令
给出删停顿、镜头时长、字幕、音乐、原声、转场、调色的明确建议。

## 发布包装
提供5个标题、12字以内封面文案、3–5个标签。

## 合规与事实检查
列出需客户确认的事实和可能风险。
```

### 4.3 选题节点提示词

```text
你是短视频账号的资深选题策划。请为下面这个真实账号生成3个原创主题。

要求：
1. 账号匹配、业务真实、今天能拍、对目标客户有明确价值，比追热点更重要。
2. 不得虚构顾客、案例、价格、资质、检测结果或当天发生的事件。
3. 不知道实时热点时不要假装有热点，改给常青选题。
4. 每个主题只讲一个核心观点，并说明为什么适合该账号、需要什么素材、推荐视频类型。
5. 同时给出进入脚本前可编辑的简要创作思路，不生成完整脚本。
6. 只输出JSON数组，不要Markdown，不要额外说明。
```

### 4.4 脚本修改节点提示词

```text
你是面向本地商家的专业短视频编剧。根据用户已确认的创作思路，生成一份真实、原创、可直接拍摄的完整脚本。

【硬性要求】
- 不编造顾客、案例、价格、检测结果、资质、热点或门店承诺；不确定事实明确标注“需客户确认”。
- 一个视频只讲一个核心观点，前3秒抓住目标客户，语言口语化，画面与拍摄条件匹配。
- 参考质量样板的具体、口语、分镜可执行标准，但禁止照抄主题或句子。
- 如果提供了当前脚本和修改意见，保留有效部分并根据意见完整重写。
```

## 5. LLM 测试案例与提示词优化

### 5.1 正常案例

**输入**：有账号定位、真实业务、可拍条件、参考视频逐字稿和至少一组代表画面。

**期望输出**：

- 能区分观察与推断。
- 只提炼 2–5 条有证据的机制。
- 生成一个核心观点明确的脚本。
- 分镜中的素材状态可追溯到已有素材或明确标记待补拍。

### 5.2 边界案例

| 场景 | 预期处理 |
|---|---|
| 没有可靠逐字稿 | 明确写“无可靠逐字稿”，只使用可验证元数据和画面 |
| 没有当天拍摄条件 | 只输出灵感方向，所需条件标记待确认 |
| 参考视频画面无法读取 | 输出画面为未知，不根据文件名猜测 |
| 没有历史数据 | 建立当前基线，不判断行业爆款 |
| 用户要求照搬 | 拒绝复制，改为提炼机制并生成原创版本 |
| 账号资料不完整 | 标注需补充信息，不擅自补齐客户事实 |

### 5.3 输出不稳定/幻觉案例

**问题现象**：模型可能把参考视频的数据当成当前账号数据；把画面文件名当成画面内容；生成不存在的顾客故事、价格或检测结果；输出 Markdown 包围的 JSON；一次脚本塞入多个主题。

**修复约束**：

1. 使用“观察/推断/未知”标签。
2. 明确禁止虚构顾客、价格、资质、检测结果和热点。
3. 要求关键口播引用时间点。
4. 规定结构化 JSON 输出，并在服务端解析失败时拒绝入库。
5. 要求一个视频只讲一个核心观点。
6. 所有缺失画面统一标记“待补拍”。
7. 低温度用于对标分析，高温度仅用于灵感选题；温度不是事实正确性的保证。

## 6. 竞品分析要点

本项目参考了“编导智能体/内容操作系统”类产品的常见能力，但没有把竞品宣传直接当作事实。重点比较以下维度：

- 是否能导入账号历史内容并形成可检索资产。
- 是否把账号定位、内容支柱和历史数据纳入生成上下文。
- 是否支持从对标视频提炼机制，而不是复制文本。
- 是否有人工确认、修改和版本留痕。
- 是否把发布后的真实数据回流到下一轮创作。
- 是否区分云端内容生产能力与本机剪辑工具能力。

项目的差异化方向：以真实门店可拍条件为约束，强调证据纪律、用户确认节点和可追踪的中间产物，而不是承诺自动预测播放量或完全替代人工判断。

## 7. 项目成果

以下只记录已验证能力，不虚构商业指标：

- 完成本地网页工作台 MVP，覆盖分析、选题、脚本、剪辑蓝图、发布准备和数据复盘模块。
- 建立内容解析 Agent 与脚本生成 Agent 的职责边界。
- 支持对标分析报告与可选择的账号经验沉淀。
- 支持灵感选题、精准选题和脚本确认/修改闭环。
- 建立字幕、重点文字、BGM、音效、插图、片尾等组件化修改入口。
- 建立半自动发布和数据复盘流程，避免伪造平台数据。
- 完成本地版到云端内部测试版的部署验证；云端与本机能力边界已明确。
- 通过自动化测试验证关键接口、状态流转和部分安全边界。

## 8. LLM 能力边界评估

### 能做好的部分

- 根据充分证据总结内容结构和表达机制。
- 按固定格式生成选题、脚本、分镜和发布文案。
- 根据账号知识和用户反馈进行改写。
- 生成复盘问题、对比维度和下一步实验建议。

### 不能直接保证的部分

- 不能仅凭一个视频准确预测点赞量或播放量。
- 不能保证理解所有画面细节，尤其在证据包不完整时。
- 不能替代专业剪辑师的审美和最终验收。
- 不能保证事实真实性，必须依赖资料边界和人工确认。
- 不能把“调用成功”当作“内容质量合格”。
- 不能仅靠提示词解决素材缺失、音频质量、字体资源和平台版权问题。

## 9. 后续迭代计划

### P0：稳定性

- 统一模型配置与密钥管理，避免每次生成重复输入。
- 加强结构化输出校验、失败重试和任务状态恢复。
- 为每个 Agent 保存输入证据、提示词版本和输出版本。

### P1：内容质量

- 用同一账号的多条真实发布数据建立小样本基线。
- 做提示词版本 A/B 测试，而不是凭单个案例固化规则。
- 增加事实核验清单和素材可用性检查。

### P2：生产效率

- 支持批量生成多个脚本和发布包。
- 建立可复用的视频模板、字幕组件和素材标签。
- 将局部修改与整片重渲染解耦。

### P3：产品化

- 增加登录、权限、账号隔离和对象存储。
- 引入任务队列、并发限制、成本统计和审计日志。
- 在真实样本充足后，再评估内容潜力评分和跨账号对比。
