# 测试与能力边界

## 正常案例

输入包含账号信息、逐字稿和画面文字证据时，系统应输出结构化分析、可迁移机制和原创脚本方向。

## 边界案例

| 输入问题 | 期望行为 |
|---|---|
| 没有逐字稿 | 明确标记缺少可靠口播证据 |
| 没有画面证据 | 不根据文件名猜测画面 |
| 没有发布数据 | 不使用“爆款”或预测播放量 |
| 用户要求照搬 | 只提炼机制，拒绝复制原句和身份 |
| 素材条件不明 | 标记待确认或待补拍 |

## 常见不稳定输出

- 把参考视频数据误当成当前账号数据。
- 把文件名当成画面内容。
- 自动补写不存在的顾客故事、价格或资质。
- 一条脚本包含多个互不相关主题。
- 结构化输出被 Markdown 代码围栏包裹。

## 提示词修复

1. 强制使用“观察/推断/未知”标签。
2. 明确禁止编造业务事实。
3. 要求时间点证据。
4. 要求 JSON 输出并在服务端校验。
5. 要求一个视频只讲一个核心观点。
6. 缺失素材统一标记“待补拍”。

## 能力边界

LLM 适合做证据整理、结构提炼、候选脚本和复盘建议；不适合单凭一个视频预测传播结果，也不能替代事实核验、专业剪辑审美或平台版权判断。
