# 珠宝商品 AI 素材生成 Agent｜测试与边界

## 1. 正常案例

**输入**：多角度戒指图片、材质/类别/必须保留纹样、渠道为电商、比例 1:1、形式为质感棚拍。

**期望**：身份解析能列出轮廓和主石约束；构图节点只改变背景与光线；生成结果进入“待人工审核”，并显示原图对比与风险清单。

**验证重点**：没有新增首饰、没有改变主石数量，输出字段完整。

## 2. 边界案例

| 场景 | 处理策略 |
|---|---|
| 只有一张图且角度遮挡 | 标记信息不足，要求补拍，不直接生成正式套图 |
| 原图带价格文字/水印 | 标记文字区域，不能擅自把文字当商品细节；进入清理或人工确认 |
| 用户未填写材质或重量 | 输出 `unknown`，禁止模型猜测 |
| 模特佩戴部位与品类冲突 | 阻止生成并请求确认 |
| 想要“更夸张”但要求结构不变 | 只允许加强光线、景别和背景，不改变首饰本体 |
| 批量生成中一张失败 | 保留已成功图片，只重试失败项并记录费用 |

## 3. 反面案例与修复

### 案例 A：把风格参考图中的首饰带入商品

- **问题现象**：模型复制了参考图的链节或宝石。
- **约束修复**：在解析和生成提示词中明确“参考图只迁移场景、光线和构图，不迁移商品本体”；质检增加额外部件检查。

### 案例 B：多轮修改后商品结构漂移

- **问题现象**：用户连续修改背景后，戒指轮廓或纹样发生变化。
- **约束修复**：每次请求重新注入 `product_identity` 与 `must_keep`，保存 `parent_version_id`，优先采用局部重绘而不是整图重生。

### 案例 C：模型用自然语言掩盖不确定性

- **问题现象**：模型声称“已保持真实”，但细节实际不可见。
- **约束修复**：要求输出可观察证据和 `uncertain_features`；质检节点只能给人工审核建议，不能直接判定真伪。

## 4. LLM/视觉模型能力边界

- 模型能帮助整理商品资料、规划构图和标记风险，但不能替代店员确认贵重商品真伪。
- 细小纹样、镂空、链节、反光和佩戴遮挡是高风险区域；必须保留原图对比。
- 没有真实盲测数据时，不能承诺固定首轮通过率、固定成本或“完全不改款”。
- 自动一致性检查是辅助筛选，不是法律、质检或交易凭证。
- 公开演示应使用合成或脱敏数据，API Key 只保存在后端环境，不进入浏览器或仓库。

## 5. 建议验收指标

用约 30 件代表性商品做盲测，记录：商品一致性、细节质感、佩戴自然度、构图可用性、首轮通过率、重试次数、平均耗时和单件成本。先建立基线，再决定主模型和正式交付规则。
