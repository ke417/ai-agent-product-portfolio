# 门店业务管账系统

## 1. 项目背景与目标

珠宝门店的回收、销售、加工、抵押和历史压存业务往往分散在纸张、表格和聊天记录中，容易出现重复录入、到期遗漏、利润口径不一致和权限边界不清。项目把高频门店业务统一为可查询、可提醒、可对账的台账。

目标：让店员快速录入，店长能查看经营和风险，系统能围绕一笔业务保留生命周期记录，并支持到期提醒、利润/提成核算和导出审计。

## 2. 角色与业务闭环

- 店员：新建业务、上传凭证、维护客户与商品信息、处理本人待办。
- 店长/主管：审核、修改关键字段、处理预警、查看利润与提成、导出对账。
- 系统任务：按到期日生成提醒，记录处理状态，不替人工做不可逆的业务决策。

```text
录入客户与商品 → 估价/业务登记 → 审核确认 → 台账查询
→ 到期提醒/续期/赎回或结清 → 利润与提成核算 → 对账导出与审计
```

## 3. MVP 模块

1. 回收、销售、加工、抵押和历史压存的独立入口。
2. 统一客户、商品、金额、日期、凭证和经手人字段。
3. 抵押台账生命周期：登记、到期、续期、赎回、结清、逾期。
4. 到期预警：按时间窗口筛选，支持待处理、已联系、已续期、已结清等状态。
5. 利润与提成：明确本金、手续费、利润和员工提成口径，明细可追溯到原始业务。
6. 软删除、回收站与恢复，降低误操作风险；关键操作保留审计记录。

## 4. 产品设计取舍

- 用“业务类型 + 生命周期”组织页面，避免首页塞入所有字段。
- 关键指标先显示总览，再按门店、员工、日期和业务单据下钻。
- 敏感金额和客户资料按角色可见，导出需要权限。
- 历史压存作为独立迁移入口，避免把历史数据混入当日新增业务。
- 提醒是辅助工具，最终联系、续期、赎回和结算仍由人工确认。

## 5. 交付成果与现存边界

- 已将分散台账流程整理为录入—审核—查询—提醒—结算闭环。
- 已形成适合私有化部署的业务模块、权限边界、回收站和数据核对思路。
- 公开作品集只展示脱敏后的流程与产品决策，不展示真实客户、联系方式、服务器、短信配置或经营数据。
- 不把系统包装成 Agent 或提示词产品：该案例的价值在于业务建模、风险控制、数据口径和落地实施。

## 6. 后续迭代

补齐多门店隔离、备份恢复演练、操作审计、消息通道适配、批量导入校验、报表权限和移动端弱网体验；上线前用隔离测试库复核金额、日期、到期和删除恢复等关键路径。
