# 轻量加工计件系统

## 1. 项目背景与目标

小型加工场常用纸质工票、口头交接或分散表格记录订单、箱号、工序和工资，管理者难以回答“这箱货在哪里、谁负责、出了什么问题、工资怎么算”。项目聚焦加工执行层，不替代完整 ERP。

目标是用稳定箱码串起订单、工序、交接、质检、返工和计件工资，降低现场录入与追责成本，并让员工端以扫码为主要入口。

## 2. 角色与业务流程

- 管理员/主管：建单、配置工序与工价、分箱、派工、监控异常、确认工资。
- 员工：登录、扫码开始/完成本人被分配的工序、提交异常、接收下一工序。
- 质检：确认合格、返工、缺件或报废数量。

```text
建单 → 工序拆解 → 分箱并生成箱码 → 派工打印
→ 员工扫码开始/完成 → 下一工序接收/退回
→ 终检确认 → 返工或完成 → 计件工资确认与导出
```

## 3. 核心业务规则

1. 一箱一码，同一码贯穿全部工序。
2. 扫码内容由登录身份、角色、当前工序和派工关系决定。
3. 未分配员工不能操作当前工序；同一道工序完成只计一次。
4. 员工完成数量先进入待确认，验收后才进入已确认工资。
5. 数量守恒：接收数 = 合格数 + 返工数 + 缺失/报废数。
6. 返工保留责任工序与处理状态，避免重复计薪。

## 4. MVP 交互与数据对象

管理端以“订单生产进度、瓶颈、待验收、返工和滞留箱”为首页重点；员工端以扫码为首要入口；工资采用“本月总额 → 订单/工序明细”下钻。

核心对象：工厂、用户、角色、员工、订单、颜色尺码组合、箱、工序任务、派工、扫码事件、质检/返工记录、工资分录、二维码和审计日志。

## 5. 验证结论与边界

- 已完成管理端、员工端、扫码端的可操作演示链路，覆盖建单、分箱、派工、交接、终检、返工和工资统计。
- 已将角色权限、重复扫码防护、待确认工资和返工记录纳入产品骨架。
- 当前主要用于演示与流程验证，前端模拟对象与正式服务端数据结构仍需统一，不能直接承载真实工资和生产数据。
- 不虚构自动排产能力；没有连续真实扫码数据前，只能称为规则驱动的派工建议。

## 6. 商用前优化

补齐服务端状态机、幂等与并发控制、正式账号权限、弱网补传、二维码补打/作废、工资月结、备份恢复和审计。先选一个订单或小批次双轨试运行，核对系统与纸票，再扩大范围。

> 本案例已脱敏，不包含客户名称、真实工价、员工信息或经营数据。项目没有 Agent 提示词或 LLM 工作流，因此不将其包装成 AI 项目。
